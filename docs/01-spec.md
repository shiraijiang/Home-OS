# 01 规格：目标、原则、范围

## 目标

减少生活里的重复决策，减少能量损耗。

追求高质量，但**允许为了节能主动降低标准或优先级**——降级是系统内置的正常动作，不是失败。

## 使用者

一个人使用。不做多人协作、不做同步、不做家庭成员偏好平衡。

## 核心原则

### 一、凡是需要定期手动同步状态的功能，一律不做

这是生死线。库存、体重、待办清单、预算余额、读书进度、习惯打卡——全部不做。这类功能要求人持续喂数据，没有人能坚持一个月，系统必死。

需要的信息一律靠**被动记录**或**一次性输入**积累，让系统去读，不让人去维护。

### 二、输入收口

一天只回答一次「今天几档 + 要不要肉」，所有模块共用这个结果。这是减少重复决策唯一真正起作用的地方——不是让选项更好选，而是让人少选几次。

### 三、永远做选择题，不做填空题

认出来比想出来省力。系统出初稿，人只做删除和调整。

### 四、不制造心理负担

- 不做连续打卡、不做进度条、不做成就任务
- 不做「今天没完成」的红点
- 不做需要照顾的养成对象（宠物、植物不会因为疏忽而变差）
- 偶发内容只在打开的瞬间掷骰子，不制造停留压力

## 第一版范围

三个入口：

| 入口 | 家具 | 功能 |
|---|---|---|
| 吃 | 岛台 | 抽牌决定今天怎么解决 |
| 记一笔 | 吧台 | 随手记录 |
| 设置 | 门 | 拼卡片、改牌堆、锁定季节与光 |

## 明确不做

- 菜谱数据库、食材表、冰箱库存管理、营养计算
- 家庭成员偏好系统、评分系统
- 记账明细、体重日记、待办清单、习惯打卡
- 社区、分享、多人功能
- 任何需要人工维护状态的东西

## 背景：为什么砍掉厨房相关的一切

使用者九成靠买来解决吃饭，偶尔想吃肉才做饭。所以真正重复的决策不是「做什么菜」，而是「今天买哪家、买什么」。菜谱、库存这类功能是伪需求，且维护成本极高。

做饭不是升级目标，只是档位里的一个正常选项，不催、不奖励、不记录完成率。
