# 04 美术规格

本文件用于约束 Home-OS 首页场景的持续制作。任何后续局部修改都不得重新解释整个房间。

机器可读的参数镜像在 `assets/art-spec.json`；两者冲突时以本文件为准（#72）。

## 视觉母版

用户提供的「大房间概念图」继续作为 **Default 画风、家具语义与主要布局参考**，但不再把其中右侧卧室入口 / 右侧玻璃结构视为不可修改的建筑定稿。当前正在从母版拆出正式空房建筑骨架，右侧建筑关系允许重新整理，以解决原图卧室入口与右墙关系不成立的问题。

仍锁定：

- 高位斜俯视、近似正交的镜头语言
- 开放式厨房、独立冰箱、岛台、玄关、鞋柜、衣架 / 开放式置物架等主要家具语义与相对布局
- 主景观窗与左侧墙窗的基本位置关系
- 家具比例和整体空间密度

暂不锁定：

- 右侧墙体、卧室开放入口、右侧玻璃结构的最终建筑关系；以新的空房建筑骨架确认稿为准

建筑骨架一旦确认，后续不得因为局部修改重新设计整个房间，尤其不得改变镜头、透视、房间比例、主要家具位置和比例。

优先采用局部编辑、分层和独立 sprite，不连续整图重绘。

## 手机竖屏构图规则

- logical scene：320 × 420
- working scale：4×
- working master：1280 × 1680
- target：mobile portrait
- 320×420 是**场景画布**，不是要求把房间本体做成 320:420 的狭长户型。
- 从横向 / 较宽的建筑母版适配手机时，必须保持房间几何比例和镜头语言；只能通过扩展画布、调整场景在画布中的占位、留白和 UI 区域适配。
- **禁止为了填满竖屏而纵向拉长地面、抬高后墙、改变窗户比例或重新生成更狭长的房间。**
- 前端等比例显示，不拉伸房间。
- UI 与 pixel scene 分离。
- 点击热区绑定 logical scene 坐标。
- 长屏优先使用 UI 区域 / 留白适配。
- 第一版不专门设计横屏。
- 16px grid 只作为建筑和固定家具辅助布局单位，Dynamic 不必严格按格移动。

## 镜头与几何约束

Default 不使用标准 2:1 isometric 作为生成约束。视觉描述统一为 **high-angle oblique interior view / near-orthographic projection（高位斜俯视、近似正交）**。

- 不用“30° isometric”重新推导母版。
- 建筑骨架确认后，以关键锚点坐标约束窗、墙角、正门、岛台、厨房等结构；锚点表另行建立。
- 生成图中的镜头角度数字只能作为目标值，最终以确认母版的几何锚点为准。
- 家具位置最终合成误差目标 ≤ 2 logical px；固定家具尺寸误差目标 ≤ 2%。

## 可切换画风

房间未来允许自由切换画风。

- **Default**：当前大房间概念图的视觉方向，为第一版默认画风。
- 其他画风以后可以逐套增加；当前讨论中由 ChatGPT 生成的另一版室内图可保留为未来画风方向参考，但不替代 Default，也不改变当前空间母版。
- 画风切换原则上只改变美术表现，不改变房间的功能坐标、家具语义、主要布局和交互入口。
- 同一画风内部仍必须遵守 Base / Dynamic / Environment / Lighting / Seasonal 分层。
- 不要求第一版实现画风切换功能；先保证 Default 完整可用。

未来新增画风时，应为每套画风保存独立 style reference / palette / 必要 sprite 规则，避免不同画风素材混用。

## 像素美术基准

当前用户提供的「小房间像素参考图」正式作为像素语言参考。它只负责像素颗粒粗细、轮廓阶梯感、信息密度、材质简化程度、植物像素簇和小物件简化程度，不得把该图的户型、家具布局、海景、配色或光照带入 Home-OS。

Default 的目标是 high-detail pixel illustration，不是低分辨率滤镜：

- working master 中 **1 logical px = 4×4 working px**，最终像素网格必须对齐 4px 网格。
- 主轮廓建议 1–2 logical px；家具边缘通常 1 logical px。
- 小物件最小有效特征建议不小于 2×2 logical px。
- 禁止亚像素边缘和连续 Gaussian blur。
- 直线、柜门、窗框应能看出像素阶梯。
- 木材不画大量连续木纹；混凝土和地砖不铺高频细碎噪点。
- 植物使用像素簇，不逐叶精描；金属、玻璃只用少量高光块表达体积。
- 阴影用明确色块，减少柔和渐变。
- 后续修改不得逐轮增加纹理、写实程度和像素密度。
- Dynamic sprite 必须和当前启用画风的 Base 使用同一像素密度。
- AI 生成只负责结构 / 内容草稿；最终尺寸、像素网格和调色板由统一后处理校正，不把 AI 自带的“pixel art”效果直接视为最终像素规格。

## 基础材质与色彩

- 赛璐珞式平涂，无渐变。
- 材质：清水混凝土、深色不发黄木、不锈钢、玻璃、铁艺。
- Base 整体为低饱和中性灰，不烘焙明显冷蓝或暖黄时间色。
- 暖意来自 Lighting，不来自基础材质色。
- 翠绿是环境中唯一高饱和色。
- 黄色只用于需要注意的状态以及黄色小精灵，不作为大面积环境色。
- 项目统一调色板，但色数暂不锁定；需在 Base 出图后统一测试再确定。
- 不允许每张图临时扩色。

## 分层

### Base / 固定层

长期不移动的建筑、家具和固定装饰，包括：墙、地面、正门、主景观窗的窗框 / 玻璃 / 窗帘、左侧墙的窗及百叶、确认后的右侧建筑结构、厨房主体、独立冰箱、岛台 / 吧台、玄关和鞋柜本体、衣架 / 开放式置物架本体、扫地机器人充电口 / 充电座、盆栽、鱼缸主体和固定造景、猫用品中的固定物件、水槽旁一瓶固定洗洁精、冰箱门少量固定贴饰、冰箱顶垂吊绿植、冰箱上方墙面的小方形智能面板。

猫用品贴墙自然摆放，不一字排开，不做大型猫爬架，不形成强烈宠物专区。厨房台面保持干净，不增加调味瓶、餐具、食材或小家电，以母版台面为基准（#70）。房间需要保留未来扩建的视觉可能（#71）。「记一笔」推迟后，吧台、吧台凳和岛台下木段作为纯造型保留（#65、#66）。

### Dynamic / 动态层

不得烘焙进 Base：猫、扫地机器人、黄色小精灵、钥匙、鞋、衣服、随身包、饮料、酒、杯子、食物、散落猫玩具、其他临时生活物件、电子设备的具体动态时间显示。

猫是居民，不是系统助手；不承担提醒、任务、饥饿值、好感度、健康值或每日照顾机制。黄色小精灵为 Dynamic，主色黄色；只参考《星露谷物语》祝尼魔的安静小生物氛围，不复制具体外形。

### Environment / 环境层

窗外环境独立于 Base，承载天空、远景 / 水面 / 城市、天气和季节变化。**Base 的主景观窗开口必须为可替换背景预留透明区域；窗框、玻璃表现和窗帘属于 Base，但具体窗外景色不得画入 Base。**

### Lighting / 光照层

Base 应为中性光照版本：室内灯关闭、无方向性阳光、无窗格投影、无长投影、无明显时间感，只保留最轻接触阴影。具体早朝、白天、夕方、夜晚的自然光、室内灯和光晕全部拆到 Lighting。

时间变化由 Environment + Lighting + Dynamic 共同表现。白天倾向钥匙不在挂架、玄关鞋较少、吧台凳整齐；晚上倾向钥匙回到挂架、玄关多两双鞋、吧台凳轻微错位并出现一杯酒。床不做昼夜整理变化，窗帘和百叶第一版固定。

### Seasonal / 季节层

季节变化主要通过 Environment + Lighting + 少量环境表现完成，不重新生成整个房间。室内固定家具和盆栽第一版固定；鱼缸长期保留白沙 + 糖果色造景的夏天感。

## 鱼缸

位置在鞋柜上。鱼缸主体与造景固定在 Base。透明玻璃缸，无背景板；白沙为主体；圆润景石成组摆放，有明显大小层次和留白；跳色为灰白 / 亮粉 / 薄荷绿；无鱼、无水草、无人物模型，不做珊瑚枝、假山和传统水族造景。隐藏式灯具属于 Base，灯光效果属于 Lighting。

## 猫与扫地机器人

猫本体 Dynamic。时间只改变状态概率，不建立复杂模拟。扫地机器人本体 Dynamic，充电座 Base 且靠墙。允许偶发机器人轻碰猫后停一下 / 转向；稀有事件为猫站在移动中的扫地机器人上，不弹成就、不要求点击。

## 扫地机器人充电口 / 隐居地入口

充电口本体属于 Base，扫地机器人属于 Dynamic。充电口同时是未来「隐居地」入口的物理位置。当前看起来就是正常充电设施，不可点击，不加文字、发光、箭头等入口提示，不为了未来功能改变现有构图。

## 电子钟

衣架下层电子钟显示真实系统时间（#78）。钟本体属于 Base，屏幕数字属于 Dynamic，每次渲染时贴上，不烘焙进 Base；数字使用与 Base 同密度的像素字。

## 冰箱顶装饰

已确认（#77），以母版为准，后续不得增减：冰箱顶一盆垂吊绿植，藤蔓垂到冰箱侧面；冰箱正面少量冰箱贴；冰箱上方墙面一个小方形智能面板。不得自行新增摆件，也不得为了“干净”把冰箱顶清空。

## 参考图管理

所有真正承担视觉约束的图片必须入库到 `assets/reference/`，不能只在聊天里用“那张图”指代。

- `assets/reference/scene-master-default.PNG`：Default 画风、家具语义和主要布局参考；其中右侧卧室 / 玻璃结构不再作为最终建筑结构锁定项。
- `assets/reference/pixel-style-reference.PNG`：只约束像素粗度、边缘语言和信息密度。
- `assets/reference/style-reference-alt-01.PNG`：仅作为未来可切换画风方向参考。

当前正在制作新的**空房建筑骨架参考图**。确认并入库后，它将优先约束房间外轮廓、墙体、门窗和手机竖屏中的场景占位；在此之前不得把任何 AI 中间稿当成正式结构母版。

图上的文字图例不构成规格（#74），入口、功能、时间段数、季节表现一律以 docs 为准。

## AI 美术修改硬性规则

- 每次修改优先局部编辑。
- 手机竖屏适配不得拉长或压扁房间本体。
- 建筑骨架确认后，不改变镜头、透视、房间外轮廓和主要家具位置 / 比例。
- 不因局部修改重新解释整个场景。
- 不自动增强细节、光影、材质纹理和写实程度。
- 新增会动的物件优先做独立资源。
- Base 制作阶段禁止方向性阳光、具体窗外景色、开着的灯和光晕、动态物件、设备动态显示、高光爆点、复杂反射、细密纹理和渐变。
